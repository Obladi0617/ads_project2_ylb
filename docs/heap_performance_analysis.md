# 四种最小优先队列的性能差异：本机三轮复现

日期：2026-10-25。

## 1. 实验口径

当前结果来自 Apple M1 Max（10 核、32 GiB）、macOS 26.6.2，Apple Clang 21.0.0，以 -std=c11 -O2 -Wall -Wextra 编译，算法单线程。保持 src/1.c 不变。

完整预热一次后，对 NY、COL、FLA 顺序执行三轮正式计时；每轮每图同样的 1,000 对不同源终点查询。总共 36,000 次正式查询执行，仍然是每图 1,000 对独立查询重复测量。前三轮全部纳入统计，第四轮开始后按用户要求停止，其部分数据不纳入统计。

计时用 clock() 测量整个 1,000 查询批次的 CPU 时间，排除图加载、查询生成和空间分配，包含逐查询清理。堆顺序随图轮换，各轮对同一图的顺序保持不变。

## 6. 性能差异的解释

### 二叉堆与三叉堆

两者活动队列都在连续数组中，通过位置数组定位顶点。三叉堆减少树高和交换，但每层需要检查更多孩子。旧版独立计数中，三叉堆下沉循环少约 27%–28%，交换少约 32%，key/item 比较却多约 0.5%–0.9%。本机三轮中位数相对二叉堆下降约 8.9%、8.6%、8.5%，与少走层数、减少交换的结构特征相符。缓存、分支和编译器的具体贡献没有硬件剖析数据，不能定量归因。

### Fibonacci 堆

成功 decrease-key 只占三类队列调用的 NY 6.64%、COL 3.58%、FLA 4.53%；extract-min 每批次却有约 1.36 亿至 5.32 亿次。Fibonacci 的摊还 O(1) decrease-key 作用于较少调用。insert 也有摊还常数优势，约占一半调用，但惰性插入把树合并工作推迟到取最小值时执行。

旧版计数显示每次提取平均提升约 7.1–7.5 个孩子，累计树链接达到十亿级，比较数约为二叉的 1.2 倍。优化版已避免 degree 表的全空范围扫描，取最小值仍需提升孩子、合并根和维护链表。这些是结构工作模式，不能把旧版计数换算为本次准确耗时。

### 二项堆

旧版 key/item 比较只有二叉的约 70%，但该字段不包含根表按 degree 的比较、遍历或指针更新。根表循环累计约 40.9 亿到 159.8 亿步，插入需要归并根表，提取需要查找最小根、提升孩子并整理树。较少的 key 比较不足以抵消这些维护工作。

### 共同的工作负载因素

这些路网每顶点约 2.4–2.8 条有向弧，稀疏情形下，代入 E=O(V)，数组堆与 Fibonacci 的完整搜索上界都成为 O(V log V)。旧版计数记录的队列峰值只有 1,002、1,037、1,575，二叉堆约 10–11 层。因此，一般图上的渐进优势并不直接等于这组点到点路网查询的实际优势。

所有堆空间都在计时前分配。运行中的连续活动数组访问，与节点池中的父子/兄弟/循环指针遍历，有不同的维护成本和访问模式；未测缓存缺失，局部性只能作合理解释。

## 7. 正确性与计数来源

除了四堆互相核对，还用独立 Python Floyd-Warshall 校验三个 40 顶点合成图。共 3,000 对查询、12,000 个四堆答案全部通过；包含 1,122 对不可达查询、330 个超过 32 位范围的距离，以及零权边、重边、孤立点。见 scripts/check_shortest_paths.py 和 results/reference_checks.json。

heap_internal_stats.csv 是保留的旧版独立计数，本次未重采。它只说明结构模式，不是新优化版的精确计时分解；Fibonacci 与二项堆的 root_list_steps 定义也不同。当前运行确认三轮高层操作数完全一致，但不能据此把低层计数称为本次新采数据。
